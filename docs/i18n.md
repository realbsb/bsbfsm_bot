# Локализация

## Поддерживаемые языки

- `ru` — русский (по умолчанию, fallback)
- `en` — английский
- `kz` — казахский

## Как работает

1. При первом `/start` язык определяется из `language_code` Telegram.
2. Пользователь может сменить через профиль или `/lang`.
3. Все тексты — в `locales/<code>.json`.
4. При отсутствии ключа — fallback на `ru`.

## Добавление языка

1. Скопировать `locales/ru.json` → `locales/<new>.json`.
2. Перевести значения (ключи не трогать).
3. Добавить код в `workflow/bot/texts.py`:

SUPPORTED_LOCALES = ("ru", "en", "kz", "<new>")
_TG_MAP = {
    "ru": "ru",
    "en": "en",
    "kk": "kz",
    "<tg_code>": "<new>",
}

4. Добавить в lang_kb в keyboards.py.
5. Перезапустить бота.

## Соглашения по ключам

common.* — общие
start.* — /start
profile.* — профиль
request.* — заявки
stage.* — этапы
price.* — деньги
parse.* — парсинг
purchase.* — закуп
schedule.* — планирование
finance.* — финансы
publish.* — публикации
fallback.* — анкета
roles.* — роли
stages.* — названия стадий
errors.* — ошибки

## Форматирование
Все ключи поддерживают str.format:
"request.created": "Заявка создана: #{id}\nСтатус: {stage}"
t("request.created", locale, id=123, stage="Закуп")

## Плюрализация
Пока не реализована. Если понадобится — добавить через babel:
from babel.support import Translations

## WebApp
В шаблонах Jinja текст пока не переводится. Для перевода:
1. Передавать locale в контекст.
2. Использовать фильтр t:
templates.env.filters["t"] = lambda key, loc: t(key, loc)
3. В шаблоне:
{{ 'stages.purchase' | t(locale) }}
